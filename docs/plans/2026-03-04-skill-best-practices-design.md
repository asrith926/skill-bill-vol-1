# Skill Bill — Skill Best Practices Design

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

## Summary

Upgrade the generated SKILL.md files to follow Anthropic's official "Complete Guide to Building Skills for Claude" best practices. The current SKILL.md is bare-bones — generic description, no trigger phrases, no examples, no metadata. The improved version includes WHAT + WHEN + trigger phrases in the description, a topics list, When to Use / When NOT to Use sections, example interactions, and metadata. Pro mode gets an AI-crafted description via one additional Haiku call per course.

## Architecture

Approach 3: shared template + optional Haiku enhancement. `skill_packager.py` remains the single owner of SKILL.md assembly. `refiner.py` contributes an AI-generated description for Pro mode via a `.skill_meta.json` sidecar file. No import dependencies between modules.

## Two Modes

### Base (smart template)
- Description built from course title + topic list + hardcoded trigger phrase patterns
- Topics extracted from video titles (listed as-is)
- 2-3 example interactions built mechanically from video titles + filenames
- When to Use / When NOT to Use sections (templated)
- Metadata block (author: Skill Bill, version: 1.0, source: youtube-playlist)
- No API cost

### Pro (Haiku-enhanced description + smart template body)
- Description generated by one Haiku call per course (~$0.001) using clean titles
- Topics use de-clickbaited titles
- Examples use clean titles
- Everything else same as Base
- Haiku output saved to `.skill_meta.json` in course directory

## Improved SKILL.md Template

### YAML Frontmatter

```yaml
---
name: {course-slug}
description: >
  {description — either AI-generated or template-built, under 1024 chars}
metadata:
  author: Skill Bill
  version: "1.0"
  source: youtube-playlist
---
```

**Base description template:**
```
Reference knowledge base from {course_title} ({video_count} videos) covering
{topic_1}, {topic_2}, ..., and {topic_n}. Use when user asks about these topics,
wants to reference video content, or asks "what does the course say about [topic]?"
```

**Pro description:** Generated by Haiku with course title + clean video titles as input. Includes contextual trigger phrases specific to the course content.

### Body Structure

```markdown
# {Course Title}

## Topics Covered
1. {Video 1 title}
2. {Video 2 title}
...
(First 8 if >10 videos, with "... and N more")

## When to Use
- User asks about a topic covered in this course
- User wants to reference or quote specific video content
- User asks "what did [creator] say about [topic]?"
- User is building content related to these topics

## When NOT to Use
- User asks about topics not covered in this course
- User needs real-time or up-to-date information (this is a static knowledge base)
- User needs general knowledge not specific to this course

## How to Use

### Step 1: Read the index
Read `index.md` for a numbered list of all {video_count} videos with links.

### Step 2: Read only the relevant video file
Each video file is 3-9K tokens. **Never load all files at once.** Read only the specific video relevant to the question.

### Step 3: Navigate by chapter
Each video file has chapter sections marked with `## [MM:SS] Chapter Title`. Use these to jump to the relevant section rather than reading the entire transcript.

## Examples

Example 1: "{example query about video 1 topic}"
1. Read index.md
2. Find video 1: {video 1 title}
3. Read {video 1 filename}
4. Navigate to relevant chapter headings

Example 2: "{example query about middle video topic}"
1. Read index.md
2. Find video {n}: {video n title}
3. Read {video n filename}

Example 3: "{broad topic question}"
1. Read index.md
2. Scan titles for relevant videos
3. Read the most relevant file(s)

## File Structure

Each video file contains:
- **Metadata header** — course name, video number, duration, source URL
- **Chapter sections** — `## [MM:SS] Chapter Title` with transcript text
- **Inline screenshots** — `![reason](./assets/NN/MM-SS.png)` (if generated with screenshots)
- **Linked Resources** — URLs from the video description
```

## Haiku Description Generation (Pro Only)

One call per course, after all videos are refined.

**Input:**
- Course title
- Numbered list of clean video titles

**Prompt:**
```
You are generating a YAML description field for a Claude Code skill file.
The skill is a knowledge base from a YouTube course.

Course: "{course_title}"
Videos:
{numbered list of clean video titles}

Generate a description under 1024 characters that includes:
1. What this knowledge base contains (1 sentence)
2. Key topics covered (comma-separated)
3. Trigger phrases — specific things a user might say that should activate this skill (3-5 phrases)

Format: A single paragraph. No YAML markers, no quotes, no newlines.
Return ONLY the description text, nothing else.
```

**Output saved to:** `{course_dir}/.skill_meta.json`
```json
{"ai_description": "Reference knowledge base from..."}
```

**Cost:** ~$0.001 per course.

## Data Flow

```
Pipeline completes (Base or Pro)
    ↓
Download route calls package_course_as_zip()
    ↓
skill_packager reads course_dir:
  - index.md → extract video titles for topics list
  - video filenames → build example interactions
  - course metadata (title, slug, video count)
    ↓
skill_packager checks for .skill_meta.json:
  - Found → use ai_description in frontmatter
  - Not found → use smart template description
    ↓
Assemble SKILL.md with improved template
    ↓
Package into ZIP
```

## Example Interaction Generation

Mechanical — no AI needed for either mode.

Pick 3 videos for examples: video 1, middle video, last video. For each:
1. Extract the distinctive part of the title as a natural question
2. Reference the actual filename for the navigation step

Base mode uses raw YouTube titles. Pro mode uses clean de-clickbaited titles.
